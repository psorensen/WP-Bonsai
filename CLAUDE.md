# Bonsai

Bonsai turns a production WordPress SQL dump of any size (up to 32 GB and more) into a small, scrubbed, working dump for local development. The full design is in `SPEC.md`. Read it before any change to selection or filtering logic.

## Current scope: Phase 1, local CLI

Build:

- A Go CLI named `bonsai`.
- A streaming SQL dump parser (pass 1 and pass 2 in SPEC.md).
- A DuckDB index written by pass 1.
- The keep-set builder, driven by a per-project YAML config.
- The pass 2 writer.
- The sandbox finish step in local Docker: MariaDB plus WP-CLI, scrub, term recount, validation report.

Do not build yet: any web UI, hosting, upload, auth, multisite, or the render test. If a task seems to need one of these, stop and ask.

## Commands (target shape)

```
bonsai index   <dump>  --out work/          # pass 1, writes work/index.duckdb
bonsai inspect work/                        # prints the inventory as JSON
bonsai plan    work/   --config bonsai.yml  # keep set + size estimate, no writing
bonsai build   <dump>  --config bonsai.yml --out slim.sql   # pass 1 if needed, pass 2, sandbox finish
```

## Rules

- **Never commit real dumps.** Only synthetic dumps generated by our own scripts go in `testdata/`. Real client dumps contain PII.
- **Memory stays flat.** Pass 1 and pass 2 must stream. Never load a whole table or the whole file into memory. Memory use must not grow with dump size beyond the ID sets.
- **The parser is the foundation.** Every parser change needs a round-trip test: parse, write back unchanged, import both into MariaDB, and compare row counts and checksums per table.
- **Selection logic lives in SQL on the DuckDB index**, not in Go loops, unless there is a clear reason.
- **No GPL code in the engine.** Call the scrubber through WP-CLI; do not port its PHP into Go. Check a dependency's license before adding it. MIT, BSD, and Apache 2.0 are fine.
- **Keep client details out of this repo.** No client names, table names, or configs. Examples use `example-newspaper`.
- Run `go test ./...` and `go vet ./...` before saying a task is done.

## Milestones

Work one milestone at a time. Each ends with passing tests and a short summary for review.

1. Parser round trip.
2. Pass 1 index and `bonsai inspect`.
3. Keep-set builder and `bonsai plan` with size estimate.
4. Pass 2 writer.
5. Sandbox finish: scrub, recount, validation report.
6. Full run on a large dump, with time and peak memory recorded.
